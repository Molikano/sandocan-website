Overview

Introduction to Sandokan

A from-scratch C++ neural network training engine. No Python. No PyTorch dependency. Drop a single header into any C++ project and get a complete training pipeline.

Sandokan gives you classification, regression, custom datasets, optimizers, learning rate schedules, and model persistence — all backed by a custom slab allocator and Apple AMX acceleration.

Single header. Everything you need lives in <sandokan.h>. Submodule headers like sandokan/io.h and sandokan/inference.h extend the core.

Quick Start

Define your network, allocate the gradient slab, attach an optimizer, and call the training loop. Everything else is handled for you.

C++
#include <sandokan.h>

struct LetterNet : Module {
    Submodule<Linear> proj { *this, 784, 64 };
    ReLU                relu;
    Submodule<Linear> head { *this, 64,  26 };

    MatrixXf forward(const MatrixXf& x) override {
        return head.forward(relu.forward(proj.forward(x)));
    }
    MatrixXf backward(const MatrixXf& dy) override {
        return proj.backward(relu.backward(head.backward(dy)));
    }
};

int main() {
    LetterNet net;
    init_pmad_for(net);   // allocate gradient slab

    ImageDataset train = load_emnist_letters("data/Emnist", true);
    ImageDataset test  = load_emnist_letters("data/Emnist", false);
    train.compute_normalization();
    test.apply_normalization_from(train);

    Adam optim(1e-3f);
    train_module(net, optim, train, test, 150, 128);
}
Motivation

Why Sandokan?

Training neural networks in C++ without a multi-gigabyte Python runtime dependency.

Training neural networks in C++ today means dragging in LibTorch — a ~1 GB dependency with a Python runtime assumption — or writing raw BLAS calls with no abstraction. Sandokan fills the gap.

A PyTorch-style API at native C++ speed, designed for environments where Python is not an option.

Target Environments

  • Embedded systems and edge devices
  • Game engines requiring on-device learning
  • Trading systems and latency-sensitive C++ codebases
  • Any pipeline where adding a Python runtime is not acceptable

Core constraint: training must be fast, deterministic, and portable — with zero dynamic allocation in the hot path.

Getting Started

Build & Install

Requirements: C++17, CMake ≥ 3.15, Eigen 3.

Homebrew (recommended)

bash
brew install sandokan

From Source

bash
cmake -B build .
cmake --build build -j

CMake Integration

cmake
# CMakeLists.txt
find_package(sandokan REQUIRED)
target_link_libraries(your_target PRIVATE sandokan::sandokan)

Apple AMX Acceleration

Strongly recommended on Apple Silicon. Unlocks batched GEMM via Apple Accelerate and the AMX co-processor.

cmake
target_compile_definitions(sandokan INTERFACE EIGEN_USE_BLAS)
target_link_libraries(sandokan INTERFACE "-framework Accelerate")

PMAD Memory Mapping

cmake
set(SANDOKAN_USE_PMAD ON)
Core API

Module System

Define networks by composing typed submodules. Auto-registration means you cannot accidentally miss a register call.

Submodule<T> auto-registers with the parent module on construction. The topology is fully known at construction time, which is what allows the PMAD allocator to compute slab sizes in a single pass.

Basic Network

C++
struct LetterNet : Module {
    Submodule<Linear> proj { *this, 784, 64 };
    ReLU                relu;
    Submodule<Linear> head { *this, 64,  26 };

    MatrixXf forward(const MatrixXf& x) override {
        return head.forward(relu.forward(proj.forward(x)));
    }
    MatrixXf backward(const MatrixXf& dy) override {
        return proj.backward(relu.backward(head.backward(dy)));
    }
};

Residual Blocks

Residual connections are first-class — the skip connection is just + x or + dy in the forward and backward passes respectively.

C++
struct ResBlock : Module {
    Submodule<Linear> fc1 { *this, 64, 64 };
    ReLU              relu1;
    Submodule<Linear> fc2 { *this, 64, 64 };
    ReLU              relu2;

    MatrixXf forward(const MatrixXf& x) override {
        return relu2.forward(
            fc2.forward(relu1.forward(fc1.forward(x)))
        ) + x;
    }
    MatrixXf backward(const MatrixXf& dy) override {
        return fc1.backward(
            relu1.backward(fc2.backward(relu2.backward(dy)))
        ) + dy;
    }
};
Memory

PMAD Slab Allocator

Zero malloc / free during training. Gradient buffers live in a single contiguous pre-allocated slab.

Size classes are derived automatically from the network topology. Once init_pmad_for() is called, all gradient buffers are migrated into the slab in a single pass. No fragmentation over long runs.

C++
LetterNet net;
init_pmad_for(net);
// reads topology, allocates slab,
// migrates gradients — in one pass.

Why it matters: combined with Apple Accelerate / AMX for batched GEMM, the PMAD allocator is the primary reason Sandokan's batched path is 19.5× faster than single-sample mode.

To enable PMAD memory mapping in CMake, set SANDOKAN_USE_PMAD ON before calling find_package.

Training

Optimizers & Schedulers

SGD and Adam out of the box. LinearLR decay with automatic scheduler stepping.

Optimizers

OptimizerConstructorNotes
SGDSGD(lr)Stochastic gradient descent with fixed learning rate
AdamAdam(lr)Adaptive moments with bias correction

Learning Rate Schedulers

SchedulerConstructorNotes
LinearLRLinearLR(optim, epochs, end_lr)Linearly decays lr from start to end_lr over N epochs

Example

C++
Adam     optim(1e-3f);
LinearLR sched(optim, 150, 1e-5f);

train_module(net, sched, train_set, test_set, 150, 128);

Both train_module and train_regression call optim.epoch_end() automatically at the end of each epoch, which triggers the scheduler step when a scheduler is provided.

Data

Dataset Abstractions

mmap-backed image loading and column-major tabular storage. RSS stays bounded regardless of dataset size.

ImageDataset

mmap-backed IDX loader. Images are page-faulted on demand — RSS stays bounded regardless of dataset size.

C++
ImageDataset train = load_emnist_letters("data/Emnist Letters", true);
ImageDataset test  = load_fashion_mnist("data/Fashion MNIST",   false);
train.compute_normalization();
test.apply_normalization_from(train);

TabularDataset

In-memory column-major store for numeric CSVs or Eigen matrices.

C++
// From CSV — last column is the target by default
TabularDataset ds = load_csv("boston.csv");
ds.compute_normalization();
ds.compute_target_normalization();

// From Eigen matrices
TabularDataset ds = TabularDataset::from_matrices(X_features, y_targets);
Training

Training Loops

One call to kick off training. Shuffling, batching, and scheduler stepping are handled automatically.

C++
// Classification — cross-entropy loss + accuracy per epoch
train_module(net, optim, train_set, test_set, epochs, batch_size);

// Regression — normalises targets, reports RMSE in original units
train_regression(net, optim, train_set, test_set, epochs, batch_size);

Both loops shuffle each epoch, skip partial batches, and call optim.epoch_end() for scheduler stepping.

Regression note: train_regression normalises targets automatically during training and de-normalises RMSE back into original units for reporting.

I/O

Model Persistence

Custom .sand binary format — compact, versioned, and normalisation-aware.

The .sand format uses a 4-word header, an optional normalisation block, and Linear weight blocks in DFS traversal order. Include sandokan/io.h to use it.

C++
#include <sandokan/io.h>

// Save weights only
save_model(net, "letter_net.sand");

// Save weights + normalisation state
save_model<TabularDataset>(net, "model.sand", ds);

// Load
load_model(net, "letter_net.sand");
load_model<TabularDataset>(net, "model.sand", ds);

Inference

Predict, rank top-K results, and display ASCII visualizations. Include sandokan/inference.h.

C++
#include <sandokan/inference.h>

// Single prediction — {label, confidence}
auto pred = predict(net, x);

// Top-K predictions
auto topk = predict_topk(net, x, 5);

// ASCII art preview + ranked confidence list
show_prediction(raw_image, true_label, topk, label_names);
